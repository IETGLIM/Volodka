## Критические находки

1. **КРОССФЕЙД OGG СЛОМАН (v4.53.0, P0).** `SceneAudioController.setStoryAudioFile`:
   `fadeOutStoryAudioElement()` взводит interval уходащего лупа, после чего
   `fadeInStoryAudioElement()` **синхронно** вызывает `clearStoryAudioFadeTimer()`
   — общий `storyAudioFadeTimer` один на контроллер, fade-in убивает fade-out до
   первого тика (90 мс). Подтверждено Node-симуляцией логики: после смены A→B
   элемент A — `paused=false, volume=0.5` спустя секунды; он не ссылается ни
   откуда, паузу даст только GC (играющий медиа-элемент GC-защищён) → каждый
   переход между story-нодами **наслаивает ещё один луп на полной громкости**.
   Ирония: при mute (target ≤ 0.001) fade-in выходит рано и fade-out успевает —
   баг проявляется ровно когда звук слышен. Тестов на story-кроссфейд нет
   (`SceneAudioController.test.ts` покрывает только scene-bed `fadeOutAll`).
   Лечение: per-element таймеры (Map/Set) — полдня.
2. **`player:roll` — событие-сирота (v4.52.0, P2).** Единственный эмит в
   `playerMainMovement`, подписчиков ноль. «Мультиканальный отклик для
   аудио/HUD» из changelog фактически = тряска + FOV-пинч. Кувырок беззвучен,
   индикатора кулдауна нет (хотя `getRollCooldown()` уже отдаёт данные).
3. **Кувырок без анимации (v4.52.0, P2).** В клип-резолюции только
   idle/walk/run — во время кувырка модель бежит run-клипом на 8.2 м/с.
   Визуально это «рывок», а не кувырок; changelog это не проговаривает
   (нарушение собственной дисциплины честности отчёта).
4. **Changelog противоречит коду по защите в бою (v4.52.0, P3).** Заявлено
   «защита осталась на Q», фактически в бою defend = клавиша **2**
   (`useCombatUiController`), а `GamepadButtonPrompt` до сих пор показывает
   игроку `defend: keyboardKey 'Q'` — устаревшая подсказка в UI.

## Риски

1. **e2e-гейт не гонялся (процесс, P1).** `e2e/act1-smoke.spec.ts:85` именно и
   проверяет `game-hud` toBeVisible — тот класс регрессии, который выстрелил в
   v4.51.0 и дожил до v4.54.0. Но `npm run check` не содержит e2e — баг ловился
   вручную и по случайности. Любой следующий CSS/класс-рефактор может повторить
   историю.
2. **Хвосты чистки v4.54.0.** Stale-комментарий в ExplorationHUD ссылается на
   удалённый hud-filmic-ambient.css; ветка `.hud-atmosphere-scan` в TSX жива под
   `!CLASSIC_UI`, а её CSS удалён (при возврате filmic-режима сканлайн станет
   голым div'ом); volodka-skin-fx.css:349 всё ещё упоминает класс в группе;
   `html.vk-classic-ui .hud-ambient-pulse` в wow-classic.css — мёртвое правило
   (класс снят с корня). Mood-vignette удалён для ОБЕИХ тем — лёгкий визуальный
   регресс filmic-режима не задокументирован.
3. **Ogg-слой не пополнялся (v4.53.0).** Все 42 ogg — старые; «разнообразие»
   актов 6–7 держится на процедурной раскраске. Файловый слой для финальных
   актов так и звучит старыми лупами (после починки кроссфейда это станет
   слышно как повтор материала).
4. **Страховочный балласт.** Список тишины wow-classic.css и блоки
   proximity/radar/ticker в volodka-skin.css оставлены сознательно — риск
   невелик, но к раунду 3 балласт стоит пометить комментариями «страховка»
   единообразно, иначе следующая чистка опять будет гадать.
